# F4 两步解读：方案（待确认后再写代码）

依据：插件需求 F4/F5；开图 main（b6d531b）的 `packages/core/src/handover.ts`、`packages/dsh-plugin/src/overview-service.ts`；Kaitu rc3 自带的 DSH 包 `dsh-llm`、`dsh-agent-default-model` 的说明。

## 1. 资料包从哪里拿：走开图插件的接口，不直接引用 `@kaitu/core`

开图的 DSH 插件已经对外提供 `remote.kaitu.handoverPack(locale, includeFinance)`，返回 `HandoverPack`：分段（目标、近 30 天结果、下一步、在做的事、方向、关于我、重要的人，开了财务权限时还有财务近况），每段带 `defaultOn`，每行已去掉密钥和本机路径；健康原始记录和标了敏感的记忆不会进来。开图自己的「在原来的 AI 里继续」用的就是它。

本插件界面加一个可选注入 `remote.kaitu`，「结合我的近况」时调这个接口。

| | 走开图接口（推荐） | 直接打包 `@kaitu/core` |
|---|---|---|
| 去密钥、去路径、敏感记忆、财务权限 | 和开图完全一致，开图改了这里自动跟上 | 复制一份规则，开图改了这边会落后 |
| 工作区在哪 | 开图知道 | 插件要自己找工作区，还要处理云盘模式 |
| 包体积 | 不变 | 多打进 core 和它的依赖 |
| 没装开图（只装 DSH） | 按钮不显示，盲读照常 | 能读，但读的是别人的数据目录，越界 |

勾选规则：沿用每段的 `defaultOn`，另外按需求把「重要的人」「财务近况」默认不勾。健康和敏感记忆开图本来就不放进资料包，界面上写一句「健康原始记录和敏感记忆不会带上」。

## 2. 盲读和结合近况怎么调模型

- 后端用 DSH 的 `ctx.llm.stream`，模型取 `ctx.agentDefaultModel.currentSelection()`（用户在 DSH 里选的默认模型）。不建会话、不挂任何工具，所以模型碰不到开图和本插件的工具。
- **盲读**：消息里只有引擎算出的结构化结果（八字、紫微、星盘或这次抽到的牌）和提示词。提示词要求分三层输出：「计算事实」「传统解读」「可以想想的问题」；干支、星位、牌面只能引用给出的结果，不许补或改。F5 的边界（不做医疗、投资、法律判断；不说宿命、吓人的话）一起写进提示词。
- **结合近况**：用户勾好、点「确认带上这些」后，把盲读结果和所选几段的原文交给模型。资料只在用户确认后才离开开图。
- 回答边生成边推到页面；这属于「等外部」那一档，界面先说明「正在解读」，不卡页面。

## 3. 存在哪里、怎么回看、怎么删

- 每次解读存成 `$DSH_HOME/kaitu-fortune/readings/<日期>-<id>.json`：类型（盲读或结合近况）、用的是哪张盘或哪次抽牌、模型名、**实际发出的完整消息**和回答。
- 存下实际发出的消息有两个用处：用户能看到交给模型的到底是什么；验收第 2 条直接打开这个文件核对：盲读里没有开图资料，结合近况里只有勾选的那几段。
- 「我的资料」卡片里多一行解读条数；单条可删；现有的「删除我的资料」一并清掉。

## 4. 「放进今天」：等 N1

需求要求建议里的行动只能变成「待你采纳的建议」，走 N1 的 proposed 路径。开图 main 上还没有：
- N1（待办状态加 `proposed`）已批准，但排在验收之后。
- 现有的两条「建议」路径都不合适：今天页的日程建议要具体起止时间；项目里的 proposed 下一步要挂在某个项目下。

建议：
1. F4 第一版先不做「放进今天」按钮，盲读和结合近况照常做完。
2. N1 做的时候，请开图插件顺带对外提供一个接口，例如 `remote.kaitu.proposeTask(title, source)`：写成 proposed 待办，source 记为「命理与星象」。
3. 有了这个接口，本插件再加按钮：解读里的每条行动可以单独「放进今天」，今天页看到的是「AI 建议」，要用户采纳才算数。

第 2 步是开图那边的改动，不在本仓库里做，需要你转给做 N1 的人。
